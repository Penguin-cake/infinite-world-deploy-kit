# 参赛团队 5 分钟接入指南

1. **选提交方式。** A 轨上传 ZIP：根目录直接包含 `index.html`，ZIP ≤ 50MB、解压后 ≤ 120MB、单文件 ≤ 35MB；HTML、脚本、WASM、PCK 与素材的相对路径要保留。B 轨提交公开可访问的 **HTTPS** 游戏入口，重定向后的页面也须保持 HTTPS。

2. **读入存档。** 普通网页引入官方 [save-protocol.js](shared/save-protocol.js)，用 `WL.readSave()` 读取。Unity、Godot、Phaser 可直接复制 [adapters](adapters/) 中的脚手架。严禁写死"满血开局"或伪造数值；主角可能是 1 点血、理智受损、带诅咒或空背包进场。

3. **通关交接。** 普通网页调用 `WL.completeLevel(CONFIG, save, {exitHook: "留给下一关的一句话"})`。**不要传 `nextUrl`**：下一关地址、关序、上下家世界都由平台注入，主办方在编排时统一填写出口钩子，选手传入的 `nextUrl` / `exitHook` 不参与产出。B 轨先监听父窗口消息，发送 `IW_READY`，从 `IW_INIT_SAVE` 读入存档，最后发送一次 `{type: 'IW_SAVE', save}`；失败可发送 `{type: 'IW_FAIL', reason, fallenSave: save}`。收到消息时检查 `event.source === window.parent`。

4. **死亡处理。** 阵亡后调用 `WL.respawn()` 就近复活（不重看片头），连续阵亡计数写在 `save.player.deaths`，`WL.assist(save)` 返回 0/1/2 三档，2 档起请自行放水（降攻、提示密码等）。确实无法通关时调用 `WL.failLevel("关卡阵亡原因")`，系统会打包遗物交给下一棒，严禁死循环卡死。

5. **道具契约。** 关卡内道具不进背包，不要调用 `WL.addItem`。跨关道具 1–3 件，`effect` 必须命中宪章词表；`effect` 不合规的道具会降级为纯装饰并在控制台提示。第 4 件起自动丢弃最早的一件。

| SAVE_STATE v3 字段 | 用法 |
| --- | --- |
| `schema` | 固定为 `"v3"` |
| `level`、`world` | 当前关序与世界名，由大厅设置 |
| `player` | `hp` 当前血量，`max_hp` 上限（最多 10），`level` 人物等级（1–10），另有 `sanity`、`status`、`curses`、`deaths`（连续阵亡次数）。扣血规则由作品决定 |
| `items`、`clues` | 道具含 `id`、`name`、`type`、可选 `desc`/`relic`/`durability`，以及 `effect: {stat, value, trigger}`。跨关最多 3 件道具、交接时最多 2 条线索 |
| `exit_hook`、`prev_world`、`next_world` | 本关出口故事与前后世界。出口钩子由主办方在编排时填写，作品只需尊重并承接它 |
| `tombstone` | 失败交接记录，可含 `fallen_level`、`cause`、`epitaph`。没有记录时用 `{}` |

| 效果词条 | 取值 | 作用 |
| --- | --- | --- |
| `hp` | `+1` / `+2` | 进下一关时回血，不超过生命上限 |
| `sanity` | `+1` | 进下一关时理智 +1 |
| `max_hp` | `+1` | 进下一关时生命上限 +1（最多 10） |
| `cleanse` | `true` | 进下一关时净化 1 项诅咒 |
| `attack` | `+1` | 常驻，由下一关战斗玩法自行读取 |

`trigger` 取 `on_enter`（进下一关结算一次，刷新重进不会重复回血）或 `passive`（常驻，不自动改数值）。可结算的道具 id 会记录在 `settled` 里随存档传递，作品不要手改这个字段。

**硬红线：** 单关 90–150 秒（最长 3 分钟）；禁止 `window.top.location` / `parent.location` 顶层跳转；禁止 `alert()` / `confirm()`；禁止破第四面墙的台词；禁止商业版权音乐与未授权 IP 素材。

沙箱里没有 `allow-modals`，`alert()/confirm()` 会被浏览器直接拒绝（线上和本地 mock-runner 都一致）。用页面内的提示元素代替；本地直接用浏览器打开游戏文件不受沙箱限制，那时的弹窗行为不代表上线行为。

B 轨入口必须允许大厅 iframe 嵌入。移除 `X-Frame-Options: DENY` 或 `SAMEORIGIN`，并检查 CSP 的 `frame-ancestors`。若设置了该指令，必须明确允许实际大厅的 HTTPS 源。`frame-ancestors 'none'` 会阻止嵌入。请在大厅里试玩验证，单独打开游戏网页无法验证这一点。


平台对齐补充：入场原始快照由平台冻结，WL.readSave 返回供玩法修改的工作副本。正式旅程通过 runId 保存服务器进度，链接中无需拼接 save 或 history。初始面板由主办方出场配置供给；入口第一关忽略 URL 存档。请在收到 iw-save-ready 后重绘面板。跨关记录属于玩家自报，不作为防作弊凭据。
